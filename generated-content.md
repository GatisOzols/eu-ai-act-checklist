# Article 50(2) — Synthetic content disclosure

Use when: your product generates text, images, audio, or video output that could be confused for human-authored content.

Required: machine-readable marking on the output AND a visible label when the content is published or shared.

Source: Regulation (EU) 2024/1689, Article 50(2)
Maintainer: Disclos team — https://www.disclos.eu

---

## Visible label

Attach this label to every published artefact (image alt text, video corner overlay, document footer, audio intro).

```
This content was generated by an AI system.
```

Translations of this single line for all 24 EU official languages live in `translations.json` (in this folder) so you can pick the right one per locale.

## Machine-readable marker — text content

Embed a C2PA (Content Credentials) manifest if your pipeline supports it. For markdown / HTML output, include this metadata block at the top of the artefact:

```yaml
---
content-type: AI-generated
ai-system-provider: <your company name>
ai-model: <model name and version, e.g. gpt-4o-2024-08>
generated-at: <ISO 8601 timestamp>
prompt-id: <optional opaque ID for internal traceability>
human-review: <yes | no | partial>
disclosure-uri: https://www.disclos.eu/tools/article-50-disclosure-generator
---
```

For plain-text output without YAML support, append a one-line trailer:

```
[AI-generated by <your company name> using <model>. Generated <timestamp>.]
```

## Machine-readable marker — image, audio, video

Use C2PA Content Credentials. Reference implementation: https://github.com/contentauth/c2pa-rs

Minimum manifest fields:
- `claim_generator`: your company + model name
- `assertions[].label`: `c2pa.actions`
- `assertions[].data.actions[0].action`: `c2pa.created` (and `c2pa.ai_generated` if available in your manifest spec version)
- `signature`: cryptographic signature by your provider key

Fallback if C2PA is not available: embed EXIF or XMP metadata with a `Generator` field containing the AI system name and an `AIGenerated: true` flag.

## Exemptions

Article 50(2) does NOT require disclosure when:
- The AI is used in a standard editing process that does not substantially alter the input (Article 50(2) last sentence).
- The content is part of an evidently artistic, creative, satirical, fictional, or analogous work (Article 50(4) artistic exception, applies to deepfakes; the comparable principle informs synthetic-content disclosure in practice).

These exceptions are narrow. Default to disclosing.

## Implementation checklist

- [ ] Visible label is present on every published artefact
- [ ] Visible label is in the user's locale (use `translations.json`)
- [ ] Machine-readable marker is embedded at generation time, not stripped by downstream processing
- [ ] Disclosure survives common transformations (resize, re-encode, copy/paste)
- [ ] Documentation of the disclosure mechanism is in your technical file (Article 11 / Annex IV)

## What this template does NOT cover

- Deepfakes of real persons — see `deepfake.md` in this folder. Deepfakes have additional disclosure obligations under Article 50(4).
- High-risk content classification — if the generated content drives a decision in an Annex III area, Article 50 disclosure is necessary but not sufficient.
